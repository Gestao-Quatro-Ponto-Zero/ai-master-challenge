# Recursos e dados necessários

- Dataset CRM Sales Predictive Analytics no Kaggle (CC0), identificador
  'agungpambudi/crm-sales-predictive-analytics';
- Token de API do Kaggle em '~/.kaggle/kaggle.json' (formato padrão, usuário e chave), provido
  pelo usuário; kaggle CLI 2.2.3 instalado via pipx.


# Execução (como foi feito)

- kaggle CLI instalado com 'pipx install kaggle'; a autenticação inicial usou o token bruto em
  '~/.kaggle/access_token' via variáveis de ambiente, e o usuário depois proveu o
  '~/.kaggle/kaggle.json' padrão, que passou a ser o caminho reprodutível confirmado;
- Download com 'kaggle datasets download -d agungpambudi/crm-sales-predictive-analytics -p
  data/ --unzip'; os arquivos residem em 'data/', ignorado pelo controle de versão;
- Verificação por 'scripts/verify-dataset.lisp', que lê cada arquivo com read-csv-file, confere
  o cabeçalho completo e a contagem de registros e encerra fail-closed. Saída literal registrada:

  ```text
  [ OK  ] accounts.csv: 85 registros (esperado 85); cabecalho conforme.
  [ OK  ] products.csv: 7 registros (esperado 7); cabecalho conforme.
  [ OK  ] sales_teams.csv: 35 registros (esperado 35); cabecalho conforme.
  [ OK  ] sales_pipeline.csv: 8800 registros (esperado 8800); cabecalho conforme.
  Resultado: todos os arquivos conformes.
  ```

  O arquivo metadata.csv, com 21 linhas, serve de dicionário de campos e não integra a
  verificação canônica;
- Permissões de '~/.kaggle/kaggle.json' e '~/.kaggle/access_token' restritas a 600.


# Riscos e lições aprendidas

- O download do Kaggle exige credencial do usuário; o setup reprodutível depende de o avaliador
  prover o seu próprio token, o que consta da documentação;
- O kaggle CLI advertiu que o token estava legível por outros usuários, corrigido com chmod 600;
  reforça o princípio de segurança desde a concepção.
