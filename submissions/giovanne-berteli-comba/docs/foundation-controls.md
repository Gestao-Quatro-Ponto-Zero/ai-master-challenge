# Foundation checks and revalidation

These controls cover the working foundation, not the future application. Use
Python 3.12 (tested with 3.12.3); no third-party packages or network are required.
Run from the submission directory:

```bash
python3 -I -m unittest discover -s tests -v
python3 -I scripts/check_foundation.py
```

The second command exits nonzero on a contract error or stale/missing evidence.
It also works from the repository root with the explicit path:

```bash
python3 -I submissions/giovanne-berteli-comba/scripts/check_foundation.py
```

## Contracts and authority

The information owners remain in [the knowledge workflow](../knowledge/knowledge-workflow.md).
The challenge ID is owned by the `challenge_id` field in
[challenge context](../knowledge/challenge-context.md). The check compares the
explicit selection in AGENTS, status, README and that context against its owner.
Deleting a declaration is also an error. It checks the official F01–F07 table,
V00-before-I01 ordering, local file-link destinations and minimum OKF headers.

The check deliberately does not certify arbitrary prose consistency, full OKF/YAML
conformance, link anchors, remote URLs, human approvals, analytical correctness
or model quality. New facts need explicit contracts or review. A passing check
does not choose a dataset combination or application architecture.

## Evidence lifecycle

[The current receipt](review-evidence/foundation-current.json) records SHA-256
hashes of operational documents, the check and its tests. Its scope and actor are
explicit. It is an automated receipt, not human verification or OKF `verified`.
The [original review snapshot](review-evidence/foundation-baseline.json) remains
historical evidence, tied to its original inputs.

Any changed, deleted or newly discovered dependency causes `STALE` and a nonzero
exit until revalidation. Checking never refreshes a receipt. After reviewing the
changes and rerunning the affected checks/tests, explicitly record the new version:

```bash
python3 -I -m unittest discover -s tests -v
python3 -I scripts/check_foundation.py --record
python3 -I scripts/check_foundation.py
```

Record only after resolving conflicts at their owners and updating summaries.
`--record` reruns document checks and records hashes; it does not run application
tests or establish the correctness of a new rule, dataset or model. Keep the Git
diff of the old receipt so reviewers can inspect what changed. An old `verified`
field or report never overrides a changed input hash.

Future data/model results need their own receipt with all direct dependencies,
including outputs, code, rules, prompts/configuration and environment lockfiles.
Pass each file explicitly with repeated `--input`; checks reuse that saved list.
For example, once the referenced files actually exist:

```bash
python3 -I scripts/check_foundation.py --record \
  --receipt docs/review-evidence/data-audit-current.json \
  --input data/raw/tickets.csv --input solution/audit.py \
  --input data/audit.json
python3 -I scripts/check_foundation.py \
  --receipt docs/review-evidence/data-audit-current.json
```

These example data files do not exist yet. Register every dependency when creating
each result; the tool cannot infer undeclared data/model relationships. A matching
hash proves input identity, not quality. A stale result must be regenerated by its
own command before a new receipt is recorded. Multiple receipts are checked
separately. Files must stay inside the submission; raw data remains ignored.

## Resumption check (F04)

From the repository root, use `git ls-files submissions/giovanne-berteli-comba`
or `rg --files --hidden --no-ignore submissions/giovanne-berteli-comba -g AGENTS.md`,
then read the explicit AGENTS path and its four-file operational startup set.
Alternatively start inside the submission. The root ignore rule is preserved.

This Codex session resumed using the committed foundation and operational owners
and identified the controls as the prerequisite to D01/D02. No historical chat
was needed for that decision. The initial broad commit diff also returned archive
content; subsequent execution reads used operational files. This is not a claim
that automatic instruction discovery works at the root or in every other tool.

it is not an agent-behavior benchmark.
