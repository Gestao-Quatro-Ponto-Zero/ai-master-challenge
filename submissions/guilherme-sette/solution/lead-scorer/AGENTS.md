# Project Guardrails

This challenge is governed by `README.md` in this directory.

All implementation, modeling, data work, documentation, and product decisions must stay anchored to the Challenge 003 Lead Scorer scope:

- Build a functional tool for Sales / RevOps, not a notebook-only analysis.
- Use the real CRM dataset for accounts, products, sales teams, and sales pipeline.
- Provide scoring or prioritization logic that goes beyond sorting by value.
- Make every score explainable to a non-technical seller.
- Include setup, scoring logic, limitations, and process log evidence.
- Prefer pragmatic, useful, explainable heuristics over unsupported claims of ML precision.
- Do not expand into unrelated features, datasets, or product directions unless the user explicitly changes the scope.

If the user asks for work outside this scope, challenge the request and explain how it conflicts with the README before proceeding.

## Frontend Visual Reference

When building frontend screens for this challenge, use Untitled UI React components as the visual reference:

https://www.untitledui.com/react/components

Apply it as a style and interaction reference for operational RevOps UI patterns such as dashboards, metrics, filters, tables, tabs, sidebars, page headers, charts, badges, buttons, inputs, selects, toggles, and tooltips.

This is a visual reference, not an automatic dependency requirement. Only install or copy Untitled UI code if it fits the selected frontend stack and keeps the deliverable functional, maintainable, and aligned with the challenge README.
