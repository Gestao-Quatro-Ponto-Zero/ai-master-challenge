# Challenge 003 Data Layer

This folder is generated by `scripts/etl.py`.

## Raw

`data/raw/` contains unchanged copies of the downloaded source CSVs:

- `accounts.csv`
- `products.csv`
- `sales_teams.csv`
- `sales_pipeline.csv`
- `data_dictionary.csv`

## Processed

`data/processed/` contains standardized CSVs for the lead scoring project:

- `dim_accounts.csv`: account dimension with normalized sector, stable `account_id`, account age, revenue band, employee band, and subsidiary flag.
- `dim_products.csv`: product dimension with stable `product_id`; canonicalizes `GTXPro` to `GTX Pro`.
- `dim_sales_teams.csv`: sales team dimension with stable sales agent and manager IDs.
- `fact_sales_pipeline.csv`: standardized opportunity fact table with canonical product, normalized stage, parsed dates, lifecycle flags, and training/scoring flags.
- `opportunities_enriched.csv`: joined table across pipeline, accounts, products, and sales teams.
- `training_closed_opportunities.csv`: modeling-ready closed opportunities (`won`/`lost`) with `target_won`; excludes leakage columns such as `deal_stage`, `engage_date`, `close_date`, and `close_value`.
- `open_pipeline_for_scoring.csv`: open opportunities (`prospecting`/`engaging`) for prioritization; excludes outcome fields.
- `etl_quality_report.json`: row counts, join checks, duplicate checks, and leakage policy.

## Snapshot Assumption

The ETL uses `2017-12-31` as the CRM snapshot date because it is the latest `close_date` in the source data. This is used only for age features such as `days_open_as_of_snapshot`.

## Run

From the repository root:

```bash
python3 challenges/build-003-lead-scorer/scripts/etl.py
```
